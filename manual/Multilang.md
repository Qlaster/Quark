# Мультиязычность сайта — фронтенд

Документ для разработчика, который делает переключение языков на стороне
посетителя. Описывает контракт хранения, уже реализованную механику и что
осталось дописать.

## На чём стоит архитектура — и что в ней своего

Каждый элемент модели имеет мировой прецедент — новаторства нет
в принципах, оно в сборке:

| Наш элемент | Мировой аналог |
|---|---|
| Словарь по тексту-оригиналу (`[t]`) | Gettext (`msgid → msgstr`) |
| Ключ `zone:type:name` → секция | Symfony domain.key, Rails `en.x.y`, i18next nested keys |
| Узел с полями переводится целиком | Mozilla Fluent (message attributes), i18next object-lookup |
| Файл на язык + мерж + фолбэк | Java ResourceBundle, Android `values-en/` → `values/` |
| ini-файлы как локали | Zend_Translate Ini adapter |
| `missing()` → промахи наружу | i18next `saveMissing`, Crowdin in-context |
| Каскад `[$lang, '']` у документов | ICU/Symfony fallback chain — только у нас он явный аргумент курсора |

Чего в таком виде у других нет:

- **Маркер на узле данных, а не ключ в шаблоне.** Мир ставит `t('key')`
  в вёрстку; у нас ключ `l10n` живёт внутри структуры и тащит override
  для любых полей — надписи, иконки, классы, ссылки. Узел — самодостаточный
  элемент, шаблон про перевод не знает вообще.
- **Ключ = путь файла.** `admin:comm:talk` читается как
  `{lang}/admin/comm.ini` + `{lang}/admin/comm/talk.ini` — ленивая докачка
  с мержем от мелкого к глубокому. Обычно локаль грузится доменом целиком.
- **`''` — полноценный базовый язык.** Не «отсутствие перевода» и не код
  `default` — отдельная строка хранения с семантикой «родная версия».
  Каскад `[$lang, '']` — явная, управляемая вызывающим кодом цепочка,
  а не скрытый фолбэк рантайма.
- **`locales()` против `langs()`.** Декларация поддерживаемых языков
  в конфиге отделена от реально существующих файлов — язык можно
  объявить выключенным, не удаляя переводов.

## Модель хранения

И страницы, и объекты — **многоязычные документы по строкам**:

- `page`: одна строка на `(url, lang)`. `lang = ''` — базовая версия
  («по умолчанию»), `lang = 'en'`, `'uk'` и т.д. — переводы.
- `objects`: одна строка на `(collection, name, lang)` — то же правило.
- Базовая версия существует всегда (у страницы — обязательно; у объекта —
  по факту). Пустой `lang` — это не «без языка», это отдельная строка базы.

Перевод — это **самостоятельная строка**, а не поле базовой. Редактор страниц
и объектов умеет переключаться между строками через `?lang=`.

## Список языков

Включённые локали объявлены в `engine/facades/l10n.ini`, секция `[locales]`:

```ini
[locales]
en.head   = 'English'
en.enable = 1
ru.head   = 'Русский'
ru.enable = 1
```

Из кода: `$APP->l10n->locales(true)` — карта `{код => {head, enable, ...}}`
только включённых; `locales()` — все; `locales(false)` — выключенные.
Ключ `''` в эту карту не входит — база добавляется отдельно там, где нужна.

## Контракт: `$_COOKIE['lang']`

**Единственный источник выбора языка на фронте** — кука `lang`:

```php
// app/controllers/index.php — главный контроллер выдачи
$lang = $page['lang'] ?? $_COOKIE['lang'] ?? '';
$page = $APP->page->get($url, $lang) ?: $APP->page->get($url);
```

Семантика:

| Кука | Поведение |
|---|---|
| отсутствует / `''` | базовая версия (`lang = ''`) |
| `'en'` | точная `en`-строка; её нет → базовая (`?:`-фолбэк) |
| страница есть только в `en`, куки нет | базовый `get($url)` — первая строка любого языка |

Тот же каскад применён к объектным тегам страницы:

```php
$APP->objects->collection($collection)->lang([$lang, ''])->get($object);
```

`lang([$lang, ''])` — first-found: перевод, а нет его — база `''`.
Без куки (`$lang=''`) каскад сводится к `['']` — только база, как было
в легаси.

## Что нужно сделать на фронте

### 1. Установка куки

Куку выставляет сам фронт — любым способом, главное соблюсти контракт:

- имя: `lang`
- значение: код локали из `l10n.ini` (`en`, `uk`, ...) или `''`/удаление
  куки — возврат к базе
- `path=/`, разумный `max-age` (например, год)
- значение — только из белого списка `array_keys($APP->l10n->locales(true))`,
  иначе `get()` просто промахнётся в базу (не критично, но мусор)

**Вариант А — контроллер-сеттер** (предпочтительно, серверный):

```php
// app/controllers/lang.php → маршрут /lang?code=en
$code = $_GET['code'] ?? '';
$enabled = $APP->l10n->locales(true);
if ($code === '' || isset($enabled[$code]))
	setcookie('lang', $code, time() + 31536000, '/');
$back = $_SERVER['HTTP_REFERER'] ?? $APP->url->home();
header("Location: $back");
```

Ссылки переключателя в шаблоне сайта:

```html
<a href="{$home}lang?code=en">English</a>
<a href="{$home}lang?code=">По умолчанию</a>
```

**Вариант Б — чистый JS:**

```js
document.cookie = 'lang=en;path=/;max-age=31536000';
location.reload();
```

Подходит для статики без дополнительного контроллера.

### 2. Меню переключения

Источник пунктов — включённые локали. Самый прозрачный путь —
**provider** (тег `source` на странице дергает скрипт, возвращающий данные):

```php
// app/providers/langs.php (пример — структура провайдеров уточнить по существующим)
$locales = $APP->l10n->locales(true);
$current = $_COOKIE['lang'] ?? '';
//отдаём [{code, head, active}] — шаблон только выводит
```

Каждому пункту прилепить: `link` (вариант А) или js-handler (вариант Б),
`active` по `$_COOKIE['lang']`. Базу можно показать как пункт с `code=''`.

Важно: **url страницы не меняется** — та же `/test` отдаёт разные языковые
строки по куке. Пункт меню НЕ должен менять адрес — только куку + reload
или запрос к сеттеру с redirect back.

### 3. Что уже работает «из коробки»

- `page->get($url, $lang)` — точная языковая строка, фолбэк на базу.
- Объектные теги — каскад `[$lang, '']` автоматически.
- Провайдеры (`source`-теги) — выполняются без языкового курсора; если
  провайдеру нужен язык, он сам читает `$_COOKIE['lang']`.
- Редакторы админки (страницы и объекты) — переключатель языков,
  сохранение в языковую строку через `?lang=` / скрытое поле.

### 4. Граничные случаи

- **Страница только в переводе** (`en` есть, базы `''` нет): без куки
  `get($url)` без фильтра вернёт первую попавшуюся строку — вероятно `en`.
  Это последняя линия фолбэка, не основная семантика.
- **Объект только в переводе**: гость без куки видит пустой тег —
  легаси вело себя так же (искала только `''`). Сознательно сохранено.
- **`public`-флаг языковый**: флаг хранится в строке языка — `en`-версия
  может быть снята с публикации при опубликованной базе (и наоборот).
- **`sitemap`, `timeline`, `del`** — в админке работают по `(url, lang)`
  осмысленно; удаление из списка сносит документ целиком со всеми
  переводами и версиями.

### 5. SEO-замечание

Один url — разный контент по куке. Это сознательный выбор модели:
поисковик без куки всегда получит базовую версию. Если понадобится
отдельная индексация языков — это другая задача (префикс маршрута
`/en/...` + тот же `lang`-механизм), к текущему контракту отношения
не имеет.

## Сводка изменений в коде (уже на месте)

| Файл | Что делает |
|---|---|
| `app/controllers/index.php` | `$lang` из `$page['lang']`/куки → `get($url, $lang)` + фолбэк; объекты — каскад `[$lang,'']` |
| `app/controllers/admin/content/page/edit.php` | `?lang=` → загрузка языковой строки; `langs.list` с `link`/`active`; `langs.value` в скрытый input |
| `app/controllers/admin/content/page/save.php` | `$page['lang']` из POST/GET → `set()` пишет языковую строку; referer сохраняет `&lang=` |
| `app/controllers/admin/content/page/index.php` | схлопка строк по url; `langs[]` — карта переводов для бейджей |
| `app/controllers/admin/content/page/del.php` | удаление без `lang`/`version` — весь документ |
| `app/controllers/admin/content/page/preview.php` | POST с `lang` → `index` → превью именно редактируемого языка |
| `app/views/admin/content/page/page.list.html` | бейджи языков из `langs[]` |
| `app/views/admin/content/page/page.add.html` | переключатель + скрытый `name=lang` |

PHP 7.2 — везде `??`, без новых синтаксисов.
