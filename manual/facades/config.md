# Фасад Config

Фасад `$APP->config` — централизованное управление конфигурацией Quark Framework.
Он читает и пишет ini-файлы, превращая их в вложенные PHP-массивы, и реализует
ключевую конвенцию фреймворка: **конфиг модуля лежит рядом с его php-файлом**.

## Для чего нужен

Config — это точка входа ко всем ini-конфигурациям фреймворка: настройки фасадов,
описания каталогов, маршруты, права доступа, меню админки, параметры загрузки файлов.

**Ключевые возможности:**

- Чтение ini-файла в вложенный массив одним вызовом
- Запись массива обратно в ini с сохранением структуры
- Автоматический поиск конфига рядом с вызывающим php-файлом
- Вложенные ключи через точку (`a.b.c = value`)
- Литеральные точки в ключах через удвоение (`a..b`)
- Подключение других ini-файлов через `@include`
- Загрузка `.env`-файлов в `$_ENV`
- Кэширование распарсенных конфигов в пределах запроса

## Конвенция расположения конфигов

Главная идея фасада: **конфигурация модуля лежит в той же директории, что и его
php-файл**, с тем же именем и расширением `.ini`.

```
engine/facades/
├── catalog.php
├── catalog.ini      ← конфиг для catalog.php
├── user.php
├── user.ini
└── ...
```

```php
// Внутри engine/facades/catalog.php
$config = $APP->config->get(__FILE__);
// читает engine/facades/catalog.ini
```

Если файл не передан вообще — фасад сам определит вызывающий файл
через `debug_backtrace`:

```php
// Внутри app/controllers/admin/tools/filemanager/index.php
$config = $APP->config->get();
// читает app/controllers/admin/tools/filemanager/index.ini
```

> **Важно:** вызов `get()` без аргументов опирается на стек вызовов —
> передавайте `__FILE__` явно, если код может быть обёрнут в функцию или
> вызван из другого файла.

## API фасада

### `$APP->config->get($filename = null)`

Читает ini-файл и возвращает вложенный массив конфигурации.

```php
// Конфиг рядом с текущим файлом
$config = $APP->config->get();

// Конфиг рядом с указанным php-файлом
$config = $APP->config->get(__FILE__);

// Прямой путь к ini
$config = $APP->config->get('engine/facades/catalog.ini');

// Конфиг аддона
$menu = $APP->config->get("addons/$name/menu.ini");
```

**Возвращает:** `array` — распарсенная конфигурация, или `null` если файл не существует.

**Бросает:** `\Exception` если файл существует, но не читается или содержит ошибки.

---

### `$APP->config->set($config, $filename = null)`

Сохраняет массив конфигурации в ini-файл. Файл записывается целиком,
атомарно (`LOCK_EX`).

```php
$APP->config->set($config);              // рядом с вызывающим файлом
$APP->config->set($config, __FILE__);    // рядом с указанным php
$APP->config->set($config, $pathToIni);  // прямой путь к ini
```

**Возвращает:** результат `file_put_contents` (байты записано или `false`).

**Бросает:** `\Exception` если ключ или значение содержат перенос строки —
файл при этом **не изменяется** (запись отменяется до начала).

---

### `$APP->config->readFile($filename)`

Читает ini-файл по прямому пути, без конвенции «рядом с php».

```php
$env = $APP->config->readFile('.env');
```

**Возвращает:** `array` или `null` если файл не читается.

---

### `$APP->config->loadENV($files, $options = [])`

Загружает один или несколько env-файлов в `$_ENV`.

```php
$APP->config->loadENV(['.env', 'app/.env']);
$APP->config->loadENV('.env', ['replace' => true]);
```

**Параметры:**

| Параметр  | Описание                                                        |
|-----------|-----------------------------------------------------------------|
| `$files`  | Путь к файлу или массив путей                                   |
| `replace` | `true` — значения из файла перезаписывают `$_ENV`; `false` (по умолчанию) — существующие переменные окружения имеют приоритет |

---

### `$APP->config->fromString($string)`

Парсит ini-контент из строки, без файла.

```php
$config = $APP->config->fromString($_POST['config']['body']);
```

**Ограничение:** директива `@include` недоступна в строковых конфигах —
нет базовой директории для разрешения относительных путей.

---

### `$APP->config->toString($config)`

Сериализует массив в ini-строку.

```php
$ini = $APP->config->toString($config);
// используется для отображения конфига в textarea админки
```

## Формат ini-файлов

Quark использует расширенный ini-формат с вложенными ключами.

### Базовый синтаксис

```ini
; комментарий
# тоже комментарий (только целая строка)

root_key = "значение в корне"

[section]
key = "значение"
flag = "on"
```

### Вложенные ключи

Точка в ключе — разделитель уровней вложенности:

```ini
account.db = "account"
account.table = "account"
account.head = "Аккаунты пользователей"
```

превращается в:

```php
[
    'account' => [
        'db'    => 'account',
        'table' => 'account',
        'head'  => 'Аккаунты пользователей',
    ],
]
```

Глубина не ограничена:

```ini
account.field.login.type = "text"
account.field.login.alias = "Логин"
```

```php
[
    'account' => [
        'field' => [
            'login' => [
                'type'  => 'text',
                'alias' => 'Логин',
            ],
        ],
    ],
]
```

### Вложенные секции

Точка работает и в именах секций:

```ini
[view.form]
skin = "modal"
```

```php
['view' => ['form' => ['skin' => 'modal']]]
```

### Кавычки в значениях

Значение может быть обёрнуто в `"` или `'` — обрамляющие кавычки снимаются
при чтении:

```ini
key1 = "значение"     ; → значение
key2 = 'значение'     ; → значение
key3 = значение       ; → значение
```

Значения с кавычками внутри (например JSON) пишутся без обрамления:

```ini
preset = {"key":"action","key2":"action"}
```

### Все значения — строки

Парсер не приводит типы: `true`, `1`, `0.5` — всё приходит строками.
При записи int/float пишутся без кавычек, bool → `true`/`false`,
но при повторном чтении вернутся строками.

## Экранирование точек в ключах

Если **сама точка** должна быть частью ключа — она удваивается.
Разделитель экранируется самим собой:

```ini
; одиночная точка — разделитель
access.ivan = "view,edit"

; удвоенная точка — литеральная точка в ключе
access.ivan..petrov = "view"
```

```php
[
    'access' => [
        'ivan'        => 'view,edit',
        'ivan.petrov' => 'view',   // ключ содержит точку
    ],
]
```

Правила:

| Запись в ini      | Ключ в массиве   |
|-------------------|------------------|
| `a.b`             | `a` → `b`        |
| `a..b`            | `a.b`            |
| `a...b`           | `a.` → `b`       |
| `a....b`          | `a..b`           |

При записи (`set`/`toString`) сегменты с точками удваиваются автоматически —
round-trip гарантирован.

> Экранируется **только** точка. Все остальные символы (`\`, `*`, `@`, `/`)
> в ключах — литеральны и не требуют экранирования.

## Директива @include

Ключ `@include` подгружает другой ini-файл и сливает его содержимое
в текущий уровень вложенности:

```ini
[main]
name = "главное меню"
@include = "extra.ini"
```

`extra.ini` читается относительно директории текущего файла и сливается
с `main` через `array_replace_recursive`.

**Ограничение:** `@include` работает только в файловых конфигах.
В `fromString()` он бросает исключение — у строки нет базовой директории.

---

## Ограничения формата

| Что | Поведение |
|-----|-----------|
| `\n` / `\r` в значении | `\Exception` при записи — файл не трогается |
| `\n` / `\r` в ключе    | `\Exception` при записи |
| `=` в ключе            | Не поддерживается — `=` всегда разделитель ключ/значение |
| `key = value` без пробелов | Работает корректно (`k=v`, `k= v`, `k =v` — все формы) |
| Inline-комментарии     | Не поддерживаются — `;` в конце строки станет частью значения |
| `key[]` массивы        | Не поддерживаются — плоский ini без нативной семантики PHP |

---

## Кэширование

`get()` и `readFile()` кэшируют распарсенный результат по пути файла
в пределах одного запроса. Повторное обращение к тому же ini не читает
и не парсит файл заново.

`set()` сбрасывает кэш соответствующего пути — следующее чтение вернёт
свежие данные с диска.

> Кэш живёт только в рамках текущего запроса и не персистится
> между запросами.

---

## Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Файл не существует (`get`, `readFile`) | `null` |
| Файл есть, но не читается | `\Exception` |
| Ошибка чтения ini | `\Exception` с именем файла |
| `@include` в строковом конфиге | `\Exception` |
| `@include` на несуществующий файл | `\Exception` |
| Конфликт: ключ уже существует как скаляр, а к нему обращаются как к секции | `\Exception` |
| Перенос строки в ключе/значении при записи | `\Exception` |

## Примеры

### Чтение настроек фасада

```php
// engine/facades/cache.php
return new Cache($this->config->get());
```

### Редактирование конфига через админку

```php
// читаем текущий конфиг
$config = $APP->config->get($filename);

// меняем
$config['view']['limit'] = 100;

// сохраняем обратно
$APP->config->set($config, $filename);
```

### Работа со строковым ini (например из textarea админки)

```php
// чтение
$object = $APP->config->fromString($_POST['config']['body']);

// сериализация обратно для отображения
$body = $APP->config->toString($object);
```

### Каталог с правами доступа (пример из catalog.ini)

```ini
[list]
account.db = "account"
account.table = "account"

; все могут смотреть, только admin-* может редактировать
account.access.* = "view"
account.access.admin-* = "view,edit,delete"

; пользователь с точкой в логине — удвоенная точка
account.access.ivan..petrov = "view,edit"
```
