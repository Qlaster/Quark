# Фасад URL  
  
Фасад `$APP->url` — инструмент для работы с адресной строкой в Quark Framework.  
Он позволяет получать текущий хост, базовый путь приложения, запрошенную страницу  
и параметры запроса, а также нормализовать URL-строки.

## Для чего нужен  
  
Фасад URL решает несколько задач:  
  
- Определить, какую страницу запросил пользователь, независимо от того,  
  в какой поддиректории установлено приложение  
- Получить базовый путь для формирования абсолютных ссылок и редиректов  
- Нормализовать URL-строки (убрать двойные слеши, лишние пробелы)  
- Переопределить текущую страницу — например, при обработке алиасов  
  
Фасад корректно работает как при установке в корень домена (`example.com/`),  
так и в поддиректорию (`example.com/myapp/`).

## API фасада  
  
### `$APP->url->host()`  
  
Возвращает имя хоста без протокола.  
  
```php  
$host = $APP->url->host();  
// "example.com"  
// "localhost"  
// "myapp.local"  
```  
  
---  
  
### `$APP->url->home($verbatim = false)`  
  
Возвращает базовый путь приложения от корня сервера, всегда заканчивается `/`.  
Если приложение установлено в корень домена — вернёт `/`.  
Если в поддиректорию — вернёт `/myapp/`.  
  
По умолчанию (`$verbatim = false`) URL нормализуется через `correct()`.  
При `$verbatim = true` — возвращается как есть, без нормализации.  
  
```php  
$base = $APP->url->home();  
// "/" — если приложение в корне  
// "/myapp/" — если в поддиректории  
  
// Формирование абсолютной ссылки  
$link = $APP->url->home() . 'admin/catalogs';  
// "/admin/catalogs" или "/myapp/admin/catalogs"  
```  
  
> Используется везде, где нужна абсолютная ссылка: редиректы, `<base href>`,  
> формирование URL для шаблонов.  
  
---  
  
### `$APP->url->page($verbatim = false)`  
  
Возвращает текущую запрошенную страницу — путь относительно `home()`,  
без GET-параметров и без ведущего слеша.  
  
По умолчанию (`$verbatim = false`) URL нормализуется через `correct()`.  
При `$verbatim = true` — возвращается без нормализации.  
  
Результат кешируется в свойстве `$page` — повторные вызовы не пересчитывают значение.  
  
```php  
$page = $APP->url->page();  
// "admin/catalogs/view"  
// "admin/login"  
// "products/detail"  
// "" — главная страница  
  
// Проверка текущего раздела  
if (str_starts_with($APP->url->page(), 'admin/')) {  
    // Это административный раздел  
}  
```  
  
---  
  
### `$APP->url->uri($verbatim = false)`  
  
Возвращает полный URI запроса — путь от корня сервера вместе с GET-параметрами,  
но без домена и протокола.  
  
По умолчанию (`$verbatim = false`) URL нормализуется через `correct()`.  
При `$verbatim = true` — возвращается как есть (urldecode применяется всегда).  
  
```php  
$uri = $APP->url->uri();  
// "/admin/catalogs/view?name=account&offset=0"  
// "/products/detail?id=42"  
// "/"  
```  
  
> Отличие от `page()`: `uri()` включает GET-параметры и ведущий слеш,  
> `page()` — только путь страницы, без параметров и без слеша.  
  
---  
  
### `$APP->url->params($array_type = true)`  
  
Возвращает строку GET-параметров запроса (QUERY_STRING).  
  
> Примечание: параметр `$array_type` объявлен в интерфейсе, но в текущей реализации  
> при `$array_type = true` метод возвращает `null`. Для получения параметров  
> в виде массива используйте стандартный `$_GET`.  
  
```php  
// Получить строку параметров  
$queryString = $APP->url->params(false);  
// "name=account&offset=0&orderby=id+DESC"  
  
// Для работы с параметрами как с массивом — используйте $_GET напрямую  
$offset = $_GET['offset'] ?? 0;  
```  
  
---  
  
### `$APP->url->correct($url)`  
  
Нормализует URL-строку: убирает пробелы по краям и схлопывает двойные слеши в одинарные.  
  
```php  
$clean = $APP->url->correct('  /admin//catalogs//view  ');  
// "/admin/catalogs/view"  
  
$clean = $APP->url->correct('');  
// ""  
```  
  
> Метод вызывается автоматически внутри `home()`, `page()` и `uri()` при  
> `$verbatim = false`. Используйте его напрямую, если нужно нормализовать  
> произвольную строку.  
  
---  
  
## Свойство `$page`  
  
Публичное свойство `$page` хранит закешированное значение текущей страницы.  
Его можно переопределить напрямую — это позволяет подменить страницу для  
последующих вызовов `page()`.  
  
```php  
// Подмена страницы при обработке алиасов  
if ($alias = $APP->route->match($APP->url->page(), ['alias']))  
    $APP->url->page = $alias[0];  
  
// Теперь $APP->url->page() вернёт значение алиаса  
$page = $APP->url->page(); // "products/detail" вместо "p/42"  
```  
  
> Это единственный способ изменить то, что фасад считает «текущей страницей».  
> Используется в `index.php` для реализации системы псевдонимов URL.

## Сводная таблица методов  
  
| Метод | Возвращает | Пример результата |  
|-------|-----------|-------------------|  
| `host()` | Домен без протокола | `"example.com"` |  
| `home()` | Базовый путь приложения | `"/"` или `"/myapp/"` |  
| `page()` | Текущая страница (без параметров) | `"admin/catalogs/view"` |  
| `uri()` | Полный URI с параметрами | `"/admin/catalogs/view?name=account"` |  
| `params(false)` | Строка GET-параметров | `"name=account&offset=0"` |  
| `correct($url)` | Нормализованный URL | `"/admin/catalogs/view"` |
