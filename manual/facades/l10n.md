# Фасад L10n

Фасад `$APP->l10n` — локализация интерфейсной статики по **маркерам `l10n`**.
Узел данных помечается ключом-секцией, фасад обходит структуру и подменяет
поля узла переводами из файлов локали. Шаблон и контроллер при этом
не переписываются — переводится любое поле узла: надпись, иконка, класс,
ссылка.

Фасад — для **статики интерфейса** (подписи кнопок, заголовки, тексты форм).
Перевод документов (страницы, объекты) — отдельная система строк
`(name, lang)`, см. `Multilang.md`.

## Для чего нужен

GUI-структура страницы объявлена в компаньон-ini контроллера (`[view]`)
на исходном языке. Маркер `l10n` вешается на узел — переводы лежат
в одноимённой секции локали и заменяют поля узла точечно:

```ini
; app/controllers/admin/tools/index.ini (исходный язык)
[view]
tools.journal.head = 'Журнал'
tools.journal.icon = 'fa fa-book'
tools.journal.l10n = 'admin:tools:journal'
```

```ini
; app/l10n/en/admin/tools.ini
[admin:tools:journal]
head = "Journal"
icon = "fa fa-book"
```

```php
$content = array_replace_recursive($content, (array) $config['view']);
$content = $APP->l10n->translate($content);   //узлы с l10n-маркером переведены
```

**Контракт fail-safe:** нет маркера, нет секции, нет поля в секции —
оригинал остаётся как есть. Перевод ничего не ломает.

Переводится **любое** поле — не только текст: `head`, `icon`, `class`,
`link`, `title`, `action` — что запишет локаль в секцию.

## Модель: маркер l10n

Маркер — обычное поле узла (по умолчанию имя ключа `l10n`, настраивается
`[translate] key`). Значение — составной ключ секции `zone:type:name`:

```
node['l10n'] = 'admin:page:edit:form'
```

Секция локали с этим именем — карта `{поле => перевод}`:

```ini
[admin:page:edit:form]
url.head   = "Page address"
url.info   = "Tip: enter a new url to save a copy"
```

При обходе узел сливается `array_replace_recursive` с секцией —
переведены только объявленные в ней поля, остальные остаются исходными.
**Маркер после перевода сохраняется** — повторная локализация другим
языком работает.

Ключ маркера — это одновременно имя ini-секции и путь ленивой загрузки
(см. ниже) — уникальность `zone:type:name` обязательна.

## Файлы локалей

Каталог — `[translate] folder` (по умолчанию `app/l10n`).

| Путь | Загрузка |
|---|---|
| `{folder}/{lang}.ini` | eager, при первом обращении к языку |
| `{folder}/{lang}/*.ini` | eager — плоские файлы сливаются целиком |
| `{folder}/{lang}/{zone}/{type}/....ini` | **lazy** — по пути секции |

Ленивая докачка: для ключа `admin:comm:talk` фасад пробует
`{lang}/admin/comm.ini` и `{lang}/admin/comm/talk.ini`, найденное
сливается от мелкого к глубокому — **глубокий файл перекрывает**.
Это позволяет раскладывать переводы по файлам произвольной глубины
без расплаты по скорости: незатронутые ветки не читаются.

Ключи ini разбираются `Core_Ini_Reader` — та же грамматика, что
у компаньон-ини контроллеров: точка в ключе — вложенность,
литеральная точка — эскейп `'..'`.

Особые словарные секции:

- **`[t]`** — словарь по самому тексту-оригиналу: `[t] "Журнал" = "Journal"`.
  Используется `translate($string)` для скаляров.
- **`[auto]`** — словарь машинного перевода для `auto()`.

### Метаданные языка

Секция `[meta]` плоского `{lang}.ini` — имя для UI: `name = "English"`.
Читается `langs()`.

## Конфигурация (l10n.ini)

```ini
[translate]
enable = 1        ;локализация вкл/выкл
source = "ru"     ;язык оригинала — значения в данных/конфигах
lang   = "ru"     ;целевой язык по умолчанию (на запрос — l10n->lang())
folder = "app/l10n"
key    = "l10n"   ;имя поля-маркера в структурах

[auto]
;autofields = head,text,title   ;поля для auto() по умолчанию
trim      = 1                   ;обрезать пробелы при поиске в словаре
lowercase = 0                   ;регистронезависимый поиск (осторожно: IP, OK)

[collect]
missing = 0       ;собирать промахи в память → l10n->missing()

[locales]
en.head    = "English"
en.flag    = "🇬🇧"
en.enable  = 1
ru.head    = "Русский"
ru.flag    = "🇷🇺"
ru.enable  = 1
```

`[locales]` — **декларация** поддерживаемых языков системой (меню
переключения, списки редактора). Формат записи — свободные поля узла:
`head`, `flag`, `enable`, что угодно ещё.

## API фасада

### `translate($data, $lang = null)` — три формы входа

Язык — аргумент или текущий `lang()`. Если локализация не нужна
(выключена, язык = source, нет файла локали) — данные возвращаются
как есть.

```php
//1. Массив — рекурсивный обход узлов с маркерами l10n
$content = $APP->l10n->translate($content);
$content = $APP->l10n->translate($content, 'en');   //явный язык, состояние не меняет

//2. Строка — словарь [t], ключом служит сам текст. Промах → оригинал
$content['title'] = $APP->l10n->translate('Журнал');

//3. Список-ссылка — lookup секции локали. Промах → null (удобно с ??)
$sec  = $APP->l10n->translate(['admin:tools:journal']);          //секция целиком
$head = $APP->l10n->translate(['admin:tools:journal', 'head']);  //одно поле
```

List-форма разрешается только на верхнем уровне вызова — внутри
рекурсии numeric-массивы не считаются ссылками.

### `auto($data, $fields = null, $lang = null)` — машинный перевод

У каждого узла значения перечисленных полей ищутся в словаре `[auto]`
локали — точное совпадение → нормализованное (trim/lowercase из конфига).
Промах → оригинал.

```php
$content = $APP->l10n->auto($content, ['head', 'text']);
$content = $APP->l10n->auto($content);   //поля из [auto] autofields конфига
```

### `lang($set = null)` — целевой язык запроса

```php
$APP->l10n->lang();        //прочитать: память → конфиг lang → source
$APP->l10n->lang('en');    //установить (только память запроса)
$APP->l10n->lang('');      //сброс выбора → фолбэк на конфиг
```

Фасад не лезет в сессии/куки — персистентность выбора решает
вызывающий код (например, `$_COOKIE['lang']` → `l10n->lang()` в
autoinclude).

### `langs()` — языки, **найденные в файлах**

Скан `{folder}`: плоские `{lang}.ini` и директории `{lang}/`, плюс
`source` конфига (может не иметь файлов). Возвращает
`{code => {name, dir}}` — `name` из `[meta]` плоского `{lang}.ini` или код.

### `locales($enable = null)` — языки, **объявленные в конфиге**

Карта `{code => {head, flag, enable, ...}}` из секции `[locales]`:

```php
$APP->l10n->locales();        //все объявленные
$APP->l10n->locales(true);    //только включённые — меню переключателя
$APP->l10n->locales(false);   //выключенные
```

### `missing($flush = false)` — собранные промахи

При `[collect] missing = 1` каждый промах (нет секции, нет ключа
словаря) складывается в память: `'lang|ключ' => ['key'=>..., 'orig'=>...]`.
`missing(true)` вернёт и очистит. **Фасад файлов не пишет** —
персистентность решает контроллер (корм для редактора переводов).

## Типовой поток контроллера

```php
//1. autoinclude — общая структура (меню, head)
$content = $APP->controller->run('admin/autoinclude', ['APP'=>$APP]);

//2. merge статики компаньон-ini — исходный язык
$content = array_replace_recursive($content, (array) $config['view']);

//3. Динамика контроллера — списки, ссылки, состояния
$content['catalog']['page'] = ...;

//4. Финальная локализация — перед display
$content = $APP->l10n->translate($content);

$APP->template->file('admin/.../page.html')->display($content);
```

Порядок важен: `translate` — в конце, когда собраны все маркеры.
Значения, подставляемые **после** translate, уже не переводятся —
так сознательно подставляют runtime-тексты (`sprintf` путей и т.п.).

---

## locales() против langs()

Два разных списка — не путать:

| | `locales()` | `langs()` |
|---|---|---|
| Источник | секция `[locales]` l10n.ini | скан файлов `app/l10n/` |
| Смысл | что система **декларирует** | какие локали **реально есть** |
| Для чего | переключатель языков, `enable`-флаг | редактор переводов, диагностика |
| Поля записи | `head`, `flag`, `enable`, любые | `name`, `dir` |

Переключатель строится по `locales(true)` — язык можно объявить и
выключенным, не удаляя его файлы.

## Промахи и редактор переводов

Промах (нет секции/поля/ключа словаря) — не ошибка, оригинал остаётся.
При включённом `[collect] missing` они собираются в память запроса:
контроллер может сохранить их в файл локали — так работает заготовка
редактора переводов: прошёл по странице → собрал недостающие ключи →
дописал секцию.

```php
$APP->l10n->translate($content);
foreach ((array) $APP->l10n->missing(true) as $miss)
    //$miss['key'], $miss['orig'], язык — в ключе 'lang|key'
```
